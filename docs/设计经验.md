# Scissor 截图软件 · 设计经验整理

> 基于 Rust + Tauri 2 实现多屏选区截图过程中的踩坑与定论，供后续迭代与同类项目参考。

## 1. 产品定位与交互定调

- **主路径要对齐用户习惯**：选区截图采用「先截屏底图 → 全屏遮罩拖拽」方案（类微信），而不是在一个小弹窗里操作。
- **默认行为要轻**：截图完成后默认只复制到剪贴板；保存本地作为二次操作（「另存为」）。
- **快捷键要稳定、可预期**（本项目约定）：
  - `Ctrl+Shift+Q`：唤起主窗口
  - `Ctrl+Shift+S`：选区截图
  - `Ctrl+Shift+A`：全屏截图
- **关闭即退出**：主窗口关闭必须结束进程并释放全局快捷键 / 单实例锁，否则会出现“命令行秒退、图标打不开”。

## 2. 架构选型结论

| 模块 | 选型 | 结论 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 体积小、Rust 侧适合做截屏与系统能力 |
| 截屏 | `xcap` | 跨平台可用；多屏需自己拼/分发 |
| 全局快捷键 | `tauri-plugin-global-shortcut` | 注册失败不要阻断启动；退出时 `unregister_all` |
| 单实例 | `tauri-plugin-single-instance` | 必需；二次启动应唤起已有窗口 |
| 发行版前端 | `custom-protocol` | **禁止**用裸 `cargo build --release` 却不开该 feature，否则会去连 `localhost:1420` |
| 本地图片展示 | `protocol-asset` + 临时 PNG / data URL | 大图不要只靠 IPC 传超大 base64 |

推荐安装/打包命令：

```bash
npm run tauri build          # 正确嵌入前端
# 或至少：
cargo build --release --features tauri/custom-protocol,protocol-asset
```

用户目录安装示例：`~/.local/bin/scissor` + `~/.local/share/applications/scissor.desktop`。

## 3. 选区截图：正确心智模型

### 3.1 单屏流程（可行）

1. 隐藏应用自身窗口  
2. 延迟约 150–200ms，避免把自己截进去  
3. 截取屏幕为底图  
4. 打开全屏遮罩层，底图铺满  
5. 用户拖拽选区 → 确认裁剪 → 复制/预览  

### 3.2 多屏流程（定稿）

**不要**用“一个窗口硬铺整个虚拟桌面”当唯一方案（双屏 + Linux 窗口管理器下尺寸/坐标易翻车）。

**定稿：每块屏幕一个覆盖层窗口**

- 窗口 label：`overlay-{monitor_id}`  
- 每屏独立底图、独立拖拽  
- 确认时带上 `monitor_id`，从对应底图裁剪  
- 取消时销毁全部 `overlay-*`  

滚动截图时，把「单屏相对坐标」换算成虚拟桌面绝对坐标后再采集。

## 4. 必踩坑与对策（按严重程度）

### 4.1 覆盖层误进主界面 → 全黑 + 只看到 Scissor 面板

**现象**：主/副屏全黑，只能看到 Scissor 主界面控件。  
**根因**：窗口 label 是 `overlay-65`，前端却写了 `label === "overlay"`，条件永不成立，全部走了 `initMain()`。  
**对策**：

```ts
const isOverlay =
  label === "overlay" ||
  label.startsWith("overlay-") ||
  params.get("view") === "overlay";
```

同时创建窗口时使用：

```text
index.html?view=overlay&monitorId={id}
```

用 URL 参数做第二保险。

### 4.2 Linux 透明全屏窗口点不中

**现象**：选区拖不动、按钮点不了。  
**对策**：覆盖层使用**不透明**窗口；选区高亮用 `box-shadow` 做暗角；工具栏 `pointer-events: auto`，并阻止 mousedown 冒泡到拖拽逻辑。

### 4.3 `fullscreen(true)` 在双屏变成“小弹窗”

**现象**：选区层不是铺满显示器。  
**对策**：不用系统 fullscreen；按显示器逻辑坐标 `inner_size + position` 精确铺满每一块屏。

### 4.4 超大 base64 导致底图加载失败（黑屏）

**现象**：遮罩有了，但看不到桌面内容。  
**对策（组合拳）**：

1. 底图落到 `/tmp/scissor-overlays/mon-{id}.png`  
2. 开启 `protocol-asset`，可用 `convertFileSrc`  
3. **最稳**：Rust 侧 `eval` 直接 `img.src = 'data:image/png;base64,...'`  
4. 图片 `onload` 前不要盖黑罩  

### 4.5 关闭后无法再次打开

**现象**：进程还在，D-Bus 单实例名被占，新进程直接退出。  
**对策**：

- 主窗口 `CloseRequested` → 销毁覆盖层、注销快捷键、`single_instance::destroy`、`app.exit(0)`  
- 单实例回调里若主窗已毁，直接退出，便于用户重新启动  

### 4.6 发行版去连 localhost

**现象**：`Could not connect to localhost: Connection refused`  
**根因**：未启用 `custom-protocol`，WebView 仍指向 `devUrl`。  
**对策**：`Cargo.toml` 固定：

```toml
tauri = { version = "2", features = ["custom-protocol", "protocol-asset"] }
```

并用 `npm run tauri build` 发布。

## 5. 前端选区 UI 经验（类微信）

- 底图 `object-fit: fill` 铺满当前屏覆盖层  
- 未选区：半透明暗罩；有选区：选框 + `box-shadow: 0 0 0 9999px rgba(0,0,0,.55)` 挖洞  
- 绿色选框 + 八个锚点提示可调区域（可先做视觉，后做拖拽缩放）  
- 工具栏贴在选区下方，触底翻到上方：取消 / 重选 / 完成  
- 坐标换算用 **`imageWidth / window.innerWidth`**，比单纯 `devicePixelRatio` 更稳  

## 6. 多屏坐标注意点

本机实例子（X11）：

```text
eDP-1  primary 1920x1080+1920+0
DP-1-0          1920x1080+0+338
```

- `xcap` 的 `x/y/width/height` 与裁剪使用同一物理坐标系  
- Tauri 窗口定位用逻辑像素：`physical / scale_factor`  
- 滚动/模拟输入（`xdotool`）需要**绝对屏幕坐标** = `monitor_x + region.x`  
- **覆盖层几何优先用 Tauri `available_monitors()` 的 position/size**（按与 xcap 矩形重叠匹配），避免副屏错位/点不中  
- 副屏可交互：覆盖层 `mouseenter`/`pointerdown` 时 `setFocus()`，创建后对所有 overlay 轮流 focus + always_on_top  

## 5b. 选区微调与标注

- 选区内拖动 = 平移选框；八个锚点 = 缩放  
- 工具栏：调整 / 箭头 / 曲线 / 文本 + 取消 / 重选 / 完成  
- 标注画在选区相对坐标；有标注时前端合成 PNG，经 `confirm_annotated_capture` 提交 

## 7. 生命周期清单（建议当成验收用例）

1. 冷启动主窗口正常、图标与标题正确  
2. `Ctrl+Shift+S`：所有屏幕出现选区层，并能看到真实桌面底图  
3. 在副屏拖拽选区并完成，剪贴板有图  
4. Esc / 取消：所有覆盖层消失，回到主窗口  
5. 关闭主窗口后，进程退出；再次 `scissor` 或点图标可打开  
6. 连续两次启动：不报 `HotKey already registered`，而是唤起已有实例  
7. 发行版离线运行：不依赖 `localhost:1420`

---

**一句话总结**：多屏选区要「每屏一个覆盖层 + 正确识别 overlay 模式 + 底图用文件/data URL 直灌」；进程生命周期要「单实例 + 关闭即退出」；发行版必须「custom-protocol 嵌入前端」。这三件事决定了能不能用、稳不稳。
